# deduplication Specification

## Purpose

Finding and merging the same paper imported from several databases —
conservatively, reversibly, explainably, and stickily — so a missed duplicate
does not double-count a study and an over-eager merge does not delete one.

Rationale: `docs/spec/05-workflow-import.md` §3.

## Requirements

### Requirement: Sticky, reversible, conservative, explainable

Deduplication MUST be:

- **Sticky**: every merge and every human "not duplicates" judgement is an
  event; re-running `strata dedup` after a new import MUST never re-ask about a
  pair a human already judged.
- **Reversible**: `strata dedup --undo <canonical> <absorbed>` MUST restore a
  record and record why.
- **Conservative**: when uncertain, ask.
- **Explainable**: every automatic merge MUST store the features that drove it,
  so `strata why` can show them.

_Source: `docs/spec/05-workflow-import.md` §3.1; E2E-07 in `docs/spec/14-testing.md` §5_

#### Scenario: Late fourth import

- **GIVEN** a reviewer kept a pair as distinct during an earlier dedup pass
- **WHEN** a fourth export is imported and `strata dedup` runs again
- **THEN** the previously judged pair is not raised again

#### Scenario: Undo a wrong merge

- **WHEN** `strata dedup --undo rec_a rec_b --why "..."` runs
- **THEN** `rec_b` is restored as canonical and a `dedup-unmerge` event records the reason

### Requirement: Blocking

Candidate pairs MUST be generated by blocking; two records are compared if they
share any block key:

| Key | Definition |
|---|---|
| `doi` | Normalised DOI |
| `pmid` | PubMed id |
| `title-prefix` | First 12 characters of the normalised title, plus year |
| `author-year-vol` | Normalised first-author family name + year + volume |
| `title-lsh` | MinHash/LSH over character 3-grams of the normalised title, 128 permutations, 32 bands of 4 rows |
| `first-page` | Normalised journal + volume + first page |

Any single block MUST be capped at 2,000 members; on exceeding it the block is
split by year and a warning is emitted.

_Source: `docs/spec/05-workflow-import.md` §3.2_

#### Scenario: Title differs by a subtitle

- **GIVEN** two records whose titles differ only by an appended subtitle and share no DOI
- **WHEN** blocking runs
- **THEN** the LSH block key makes them a candidate pair

#### Scenario: Runaway block

- **GIVEN** a parse failure that put the same constant string in 3,000 titles
- **WHEN** blocking runs
- **THEN** the block is split by year and a warning is emitted

### Requirement: Scoring

For each candidate pair the system MUST compute a similarity in `[0, 1]`:

```
if both have a DOI:
    score = 1.00 if DOIs equal
    score = 0.00 if DOIs differ
else:
    score = 0.50 * title_sim + 0.20 * author_sim + 0.15 * year_sim
          + 0.10 * journal_sim + 0.05 * locator_sim
```

- `title_sim`: maximum of token-set Jaccard and normalised Levenshtein ratio on
  the sorted token string.
- `author_sim`: Jaccard over normalised family-name sets; 0.5 weight if only the
  first author is available on either side.
- `year_sim`: 1.0 if equal, 0.7 if differing by 1, 0.0 otherwise.
- `journal_sim`: normalised container-title ratio after abbreviation expansion.
- `locator_sim`: 1.0 if volume and first page both match, 0.5 if one matches.

Scoring MUST be symmetric: `score(a, b) == score(b, a)`.

DOI-mismatched pairs that score above `review_threshold` on the non-DOI features
MUST be routed to the review queue labelled `doi-conflict` rather than discarded.

_Source: `docs/spec/05-workflow-import.md` §3.3; property P8 in `docs/spec/14-testing.md` §2_

#### Scenario: Equal DOIs

- **WHEN** two records with the same normalised DOI are scored
- **THEN** the score is 1.00

#### Scenario: Different DOIs but otherwise identical

- **GIVEN** two records with DOIs differing by a `-2` suffix and matching titles, authors, and journal
- **WHEN** they are scored
- **THEN** the pair is queued for human review labelled `doi-conflict`

### Requirement: Thresholds and actions

| Score | Action |
|---|---|
| `>= auto_merge_threshold` (default 0.95) | Auto-merge; emit `dedup-merge` |
| `>= review_threshold` (default 0.80) | Queue for human review |
| `< review_threshold` | Distinct; no event recorded |

`strata dedup --strict` MUST set both thresholds to 1.0 so every non-exact pair
is reviewed.

_Source: `docs/spec/05-workflow-import.md` §3.4_

#### Scenario: Pair scoring 0.88

- **WHEN** a pair scores 0.88 at default thresholds
- **THEN** it is queued for human review and not merged

#### Scenario: Strict mode

- **WHEN** `strata dedup --strict` runs and a pair scores 0.97
- **THEN** it is queued for review rather than auto-merged

### Requirement: Merge semantics

The surviving canonical record MUST be chosen by most complete record (count of
populated DOI, abstract, authors, pages), then highest `source_trust`, then
lowest id. Fields MUST merge as follows: a field empty on the canonical and
present on the absorbed is copied; a field present on both is kept from the
higher-trust source; `abstract` takes the longest non-empty value; `keyword` is
a set union; `strata.sources` is appended; every field's origin is recorded in
`strata.field_provenance`. The absorbed record MUST be retained in
`records.ndjson` with `strata.canonical: false` and an `aliases.ndjson` entry;
nothing is deleted.

_Source: `docs/spec/05-workflow-import.md` §3.5_

#### Scenario: Truncated abstract on the canonical record

- **GIVEN** a canonical record with a truncated abstract and an absorbed record with the full abstract
- **WHEN** they are merged
- **THEN** the canonical record keeps the full abstract and `field_provenance` records its source

#### Scenario: Absorbed record retained

- **WHEN** a merge completes
- **THEN** the absorbed record remains in `records.ndjson` with `strata.canonical: false` and an alias entry exists

### Requirement: Review queue

`strata dedup --review` MUST present one pair per screen, keyboard-driven, with
the evidence visible (both records, per-feature similarities, and any
`doi-conflict` explanation), offering merge, keep both, skip, open both, and
help. Keeping both MUST record a `dedup-distinct` event so the pair is never
raised again.

_Source: `docs/spec/05-workflow-import.md` §3.6_

#### Scenario: Keep both

- **WHEN** a reviewer presses `k` on a pair
- **THEN** a `dedup-distinct` event is recorded and the pair never reappears in the queue

### Requirement: Performance

Deduplicating 50,000 records MUST complete in under 120 seconds on a 2020-era
laptop, single-threaded, and MUST NOT exceed 2 GB of resident memory.
Implementations SHOULD parallelise scoring across blocks.

_Source: `docs/spec/05-workflow-import.md` §3.7_

#### Scenario: 50,000-record dedup

- **WHEN** `strata dedup` runs over 50,000 records on reference hardware
- **THEN** it completes in under 120 seconds with peak RSS under 2 GB

### Requirement: Validation against a labelled benchmark

The dedup engine MUST be evaluated against a labelled benchmark with results
published in the repository, reporting precision, recall, F1, and — separately
and weighted most heavily — the false-merge rate. The v1 target is recall
>= 0.95 and false-merge rate <= 0.001 at default thresholds.

_Source: `docs/spec/05-workflow-import.md` §3.8_

#### Scenario: Benchmark run

- **WHEN** the benchmark is run at default thresholds
- **THEN** recall is at least 0.95 and the false-merge rate is at most 0.001
- **AND** the results are written to the published benchmark report
