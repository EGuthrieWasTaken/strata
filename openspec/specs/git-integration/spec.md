# git-integration Specification

## Purpose

How `strata` drives git as its storage engine and audit log without ever making
git the user interface: one commit per operation, structured commit messages
with machine-readable trailers, mandatory rationales, batched screening
commits, `.gitattributes` and merge drivers, versioned hooks, and repository
hygiene rules.

Rationale and worked examples: [design.md](design.md).

## Requirements

### Requirement: Git is never the user interface

A user who runs only `strata` commands MUST never see a merge conflict marker, a
detached HEAD, a rebase prompt, or the word "upstream". A user who knows git
MUST find an ordinary, well-formed repository they can branch, diff, blame, and
review with standard tools.

#### Scenario: Non-git user syncs after a collaborator screened

- **WHEN** a user who has only ever run `strata` commands syncs after a collaborator screened the same records
- **THEN** no git terminology or conflict marker is shown to them

### Requirement: One operation, one commit

Every mutating `strata` command MUST produce exactly one commit, unless
`--no-commit` is passed (which stages nothing and leaves the working tree dirty).
Batched screening is the only exception.

#### Scenario: Adding a criterion

- **WHEN** `strata criteria add ... --why "..."` completes
- **THEN** exactly one new commit exists

#### Scenario: No-commit flag

- **WHEN** a mutating command runs with `--no-commit`
- **THEN** no commit is created and nothing is staged

### Requirement: Structured commit messages

Commit messages MUST have:

- **Subject**: `<op>(<scope>): <summary>`, imperative, at most 72 characters,
  generated by `strata` from what actually changed — never typed by the user.
- **Body**: the user's rationale, wrapped at 72 columns.
- **Trailers**: machine-readable, `Strata-`-prefixed, one per line, RFC-822
  style, e.g. `Strata-Op`, `Strata-Stage`, `Strata-Actor`,
  `Strata-Records-Affected`, `Strata-Decisions`, `Strata-Criteria-Version`,
  `Strata-Criteria-Digest`, `Strata-Events`, `Strata-Pool-Delta`,
  `Strata-Schema-Version`.

`Strata-Op` values MUST be the event types plus `init`, `import`, `migrate`,
`sync`, `analyze`, `report`. A commit-msg hook MUST validate the trailer block
and reject a malformed one when `commit_style = "structured"`.

#### Scenario: Screening commit

- **WHEN** a screening batch of 180 re-screened records is committed
- **THEN** the subject reads like `screen(title-abstract): exclude 42 records under new criterion EXC-07`
- **AND** the trailers include `Strata-Op: screen`, `Strata-Stage: title-abstract`, and `Strata-Records-Affected: 180`

#### Scenario: Malformed trailer

- **WHEN** a commit is attempted with a `Strata-Op` value that is not a known operation
- **THEN** the commit-msg hook rejects it

### Requirement: Eliciting the rationale

When `git.require_rationale` is true (the default), a mutating command MUST
obtain a rationale before committing, using a prompt that tells the user what
changed so the answer is about why. The rationale:

- MUST NOT be empty or whitespace, and MUST be at least 12 characters.
- MUST NOT be one of the shipped stop-list values (`.`, `x`, `fix`, `update`,
  `wip`, `asdf`); rejection explains why the rationale matters.
- MAY be supplied with `--why "<text>"` or `--why-file <path>`.

In a non-interactive context with neither flag, the command MUST fail (exit
code 7) rather than invent a rationale.

#### Scenario: Stop-listed rationale

- **WHEN** a user answers the rationale prompt with `wip`
- **THEN** the answer is rejected with an explanation and the prompt repeats

#### Scenario: Script without a rationale

- **WHEN** a mutating command runs non-interactively without `--why` or `--why-file`
- **THEN** it exits with code 7 and makes no commit

#### Scenario: Criteria edit prompt shows the impact

- **WHEN** a user tightens `EXC-03` interactively
- **THEN** the prompt states how many screening decisions the change invalidates before asking why

### Requirement: Batched screening commits

Screening decisions MUST be appended to the event log immediately but committed
in batches: a commit is created when the user ends a session, when 200
decisions accumulate, or after 15 minutes of inactivity, whichever comes first.
A routine batch skips the rationale prompt and gets a generated summary
message. A batch containing any decision that contradicts a previously resolved
decision MUST prompt for a rationale.

#### Scenario: 200 decisions

- **WHEN** a reviewer records their 200th uncommitted decision
- **THEN** a commit is created with a generated message such as `screen(title-abstract): screen 200 records (183 exclude, 17 include)`

#### Scenario: Batch contains a change of mind

- **GIVEN** a record previously resolved `include`
- **WHEN** a batch that re-decides it as `exclude` is committed
- **THEN** the user is prompted for a rationale

### Requirement: gitattributes

`strata init` MUST write `.gitattributes` with at least:

```gitattributes
* text=auto eol=lf

events/**/*.ndjson     merge=union    -diff=nodiff
records/records.ndjson merge=strata-records
records/aliases.ndjson merge=union
derived/**             merge=strata-regenerate linguist-generated=true
reports/**             merge=strata-regenerate linguist-generated=true
analysis/results/**    merge=strata-regenerate linguist-generated=true
imports/*/raw/**       -merge -diff
*.svg                  -diff
```

#### Scenario: Fresh repository

- **WHEN** `strata init` completes
- **THEN** `.gitattributes` assigns `merge=union` to event files and `merge=strata-regenerate` to derived views

### Requirement: Merge drivers

Because merge driver definitions live in the uncommitted `.git/config`,
`strata init` and `strata doctor` MUST install them locally
(`strata-regenerate` running `strata merge-regenerate %O %A %B %P`;
`strata-records` running `strata merge-records %O %A %B %P`). `strata doctor`
MUST detect missing drivers and offer to install them. A clone without drivers
MUST still work: git falls back to its default driver and `strata sync`
resolves `derived/` conflicts by regeneration.

- `strata merge-regenerate` ignores all three inputs, writes nothing, exits 0.
- `strata merge-records` performs a three-way merge keyed by record `id`: an id
  on one side only is kept; identical ids are kept; differing ids are merged
  field-wise with `strata.sources` as a set union. For scalar fields, if one
  side equals the base the other side wins; if both changed, `dedup.source_trust`
  decides; if still tied, the longer value wins for `abstract` and the
  lexicographically smaller value otherwise, and a `record-amend` event records
  the automatic resolution. Automatic resolution MUST always be reported in
  `strata sync` output, never silent.

#### Scenario: Clone without drivers

- **GIVEN** a plain `git clone` without running `strata doctor`
- **WHEN** `strata doctor` runs
- **THEN** it reports the missing merge drivers and offers to install them

#### Scenario: Both sides changed the same abstract

- **GIVEN** both branches changed a record's abstract from the same base with equal source trust
- **WHEN** `strata merge-records` runs
- **THEN** the longer abstract is kept and a `record-amend` event records the automatic resolution

### Requirement: Versioned hooks

`strata init` MUST set `core.hooksPath = .strata/hooks` so hooks are versioned
and every collaborator gets them on clone:

| Hook | Action | Failure |
|---|---|---|
| `pre-commit` | `strata verify --fast` | blocks the commit |
| `commit-msg` | validate `Strata-` trailers when `commit_style = "structured"` | blocks the commit |
| `post-merge` | regenerate derived files, then `strata verify` | warns |
| `post-checkout` | invalidate `.strata/cache` if HEAD moved | never fails |

All hooks MUST be skippable via `STRATA_SKIP_HOOKS=1` and MUST print that the
variable exists when they block an operation.

#### Scenario: Hook blocks a commit

- **WHEN** the pre-commit hook blocks a commit because verification failed
- **THEN** its message mentions `STRATA_SKIP_HOOKS=1`

#### Scenario: Recovery bypass

- **WHEN** a commit is made with `STRATA_SKIP_HOOKS=1`
- **THEN** no strata hook runs

### Requirement: Repository hygiene

- A 50,000-record review SHOULD stay under 200 MB; `strata doctor` MUST warn
  above 500 MB and suggest `git gc`.
- Full texts MUST NOT be committed. Teams that have cleared the rights MAY set
  `fulltext.track = "lfs"`, which `strata` supports but never enables by default.
- `strata` MUST NOT rewrite published history; there is no amend for a pushed
  commit, and mistakes are corrected by a new event and a new commit.
- `strata` MUST work on whatever branch is checked out and MUST NOT require a
  pull-request workflow, though it SHOULD document that pattern for protocol
  changes.

#### Scenario: Oversized repository

- **WHEN** `strata doctor` runs on a 600 MB repository
- **THEN** it warns and suggests `git gc`

#### Scenario: Correcting a pushed mistake

- **WHEN** a user needs to correct a pushed screening decision
- **THEN** the correction is a new event in a new commit and no published commit is rewritten
