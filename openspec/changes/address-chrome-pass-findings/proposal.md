# Proposal: Address what the Chrome pass found

## Why

An agent went through `strata serve` in Chrome ([`docs/chrome-pass-results.md`](../../../docs/chrome-pass-results.md))
and filed nine issues, #83 to #91. Seven are faults or gaps in the web interface that the specification
either did not cover or covered in a way the pass showed to be wrong:

- Screening in the browser was never committed (#83). `git-integration#batched-screening-commits` names three
  triggers and a rationale prompt, all written for a terminal session; nothing said what "the user ends a
  session" means for a server, or how a commit made by a timer could prompt anyone.
- A digit key recorded an exclusion at once (#86). `web-ui#screening-surface-requirements` S3 asked for
  exactly that. A stray key excluded a record, and the log kept the mistake.
- Two servers on one host signed each other out (#85): cookies ignore ports and both named theirs
  `strata_session`.
- Messages written for the command line reached reviewers, counts with the same name counted different
  things, and pages showed who and what but not why or when (#87, #88, #90).

(#84, the PRISMA identities, is specified in `add-prisma-reporting`, which is still open, and is changed
there. #89 and #91 change no requirement: they are layout and test coverage.)

## What Changes

- **Batched screening commits say what the triggers are in the browser**, and where a changed decision's
  rationale comes from: it is asked for when the decision is made, kept in the event, and listed in the
  batch's message, so no commit ever needs a prompt.
- **A digit ticks a reason and never decides** (S3), a skipped record comes back (new S15), the counter
  counts decisions (new S16), and a refused decision keeps the reviewer's place (new S17).
- **A server's session cookie is its own**, named after the port a browser reaches it on.
- **What a reviewer is shown is in a reviewer's words**: a refusal says what is wrong and what to do with
  the setting or code beneath it; a count says what it counts; history and provenance give the reason and
  the date.

Milestone: M2 (the web interface) and M6 (its write screens), already shipped.

This does not alter identity, normalisation, canonical serialisation, the fold, or the staleness rules, and
needs no schema version bump. `derived/counts.json` gains one field and two reworded identities under
`add-prisma-reporting`; it is regenerated by the next command that commits.

### Rejected

- **Committing a changed decision at once, on its own, with a required reason** (as an adjudication is). It
  keeps the rationale in a commit of its own, but a criterion change that turns fifty decisions would make
  fifty commits, and the reason would live only in the commit message. Keeping it in the event's note puts
  it in the log, where `strata why` and the record page find it.
- **A prompt when the batch is committed.** A timer, the 200th decision and a shutdown have nobody to ask.
- **Keeping the digit-alone exclusion behind a setting.** One more setting, for a shortcut that saves one
  keystroke and costs a wrong exclusion in the permanent record whenever a key is pressed by mistake.
