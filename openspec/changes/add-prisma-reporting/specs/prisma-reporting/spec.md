# prisma-reporting Specification

## Purpose

PRISMA 2020 reporting generated from the event log: every flow-diagram count
with enforced reconciliation, the flow diagram itself in several formats, and
the 27-item checklist with each item auto-filled, auto-located, or left to the
author.

## ADDED Requirements

### Requirement: PRISMA 2020 target and attribution

`strata` MUST target the PRISMA 2020 statement (27-item checklist and flow
diagram). Box labels and checklist wording MUST be verified against the official
template before shipping, with the official wording authoritative where it
differs, and generated output MUST carry the CC BY 4.0 attribution.

#### Scenario: Generated checklist

- **WHEN** the checklist is generated
- **THEN** it carries the PRISMA 2020 attribution

### Requirement: Counts and reconciliation identities

`derived/counts.json` MUST hold every count the flow diagram needs, derived from
the event log, and the generator MUST assert each identity below, failing with
`E_COUNT_RECONCILE` naming the violated identity if any does not hold:

```
identified_total           = sum over searches of records identified (raw rows)
                           + records identified via other methods
removed_before_screening   = duplicates_removed + marked_ineligible_by_automation + removed_other
records_screened           = identified_total - removed_before_screening
records_screened           = records_excluded_tiab + reports_sought
reports_sought             = reports_retrieved + reports_not_retrieved
reports_retrieved          = reports_assessed
reports_assessed           = reports_excluded_ft + reports_included
reports_excluded_ft        = sum over exclusion reasons of count_per_reason
studies_included          <= reports_included + studies_from_split_reports
studies_included           > 0 exactly when reports_included > 0
reports_of_included_studies = reports_included
```

A study can have several reports (a grouping) and one report can describe several studies (a
split, as PRISMA 2020 allows), so `reports_of_included_studies` counts each report once however
many studies it belongs to, and `studies_from_split_reports` is the number of studies beyond one
per report that splits account for. A split is a decision, never a counting error.

Wherever a failed identity is shown to a reviewer (the web interface), it MUST be said in words
(which counts do not add up, and what to do), with the code and the identity kept for whoever has
to look them up.

`marked_ineligible_by_automation` MUST exist in the schema (0 in v1). Each count
MUST be partitioned by `via` for the two-column diagram. The identities MUST
hold for any randomly generated review history (property P11).

#### Scenario: Funnel closes

- **WHEN** counts are generated for a completed review
- **THEN** every identity holds and `counts.json` records the assertions

#### Scenario: A report split into two studies

- **GIVEN** a finished review in which one included report is split into two studies
- **WHEN** counts are generated
- **THEN** every identity holds, the studies included are one more than before and the reports of included studies are unchanged

#### Scenario: Broken identity

- **GIVEN** a history in which reports sought do not equal retrieved plus not retrieved
- **WHEN** counts are generated
- **THEN** generation fails with `E_COUNT_RECONCILE` naming that identity

### Requirement: Flow diagram

`strata prisma [--format svg|pdf|png|json] [--columns one|both]` MUST render the
PRISMA 2020 new-reviews flow diagram (identification, screening, included),
with the "other methods" column populated from records imported with `--via`.
The JSON form MUST also be emitted in the input shape of the `PRISMA2020` R
package. The diagram MUST be regenerated by `strata verify` and compared byte
for byte.

#### Scenario: Two-column diagram

- **GIVEN** records imported with `--via citation-searching`
- **WHEN** `strata prisma --columns both` runs
- **THEN** those records appear in the other-methods column

### Requirement: Exclusion reasons in the diagram

The "Reports excluded, with reasons" box MUST use the criterion labels from
`protocol/criteria.yaml` with counts from full-text exclusion events, omitting
reasons with a count of 0. If more than 6 reasons have non-zero counts, the
smallest MUST be collapsed into "Other reasons (n = )" and the full table
emitted alongside.

#### Scenario: Nine exclusion reasons

- **WHEN** nine criteria have non-zero full-text exclusion counts
- **THEN** the smallest reasons are collapsed into "Other reasons (n = )" and the full table is emitted alongside

### Requirement: Stale decisions block the final diagram

While any decision is stale, `strata prisma` MUST refuse to render unless
`--allow-stale` is passed, and the rendered diagram MUST then carry a visible
"DRAFT — screening incomplete" watermark.

#### Scenario: Draft diagram

- **GIVEN** 180 stale decisions
- **WHEN** `strata prisma --allow-stale` runs
- **THEN** the diagram is rendered with the DRAFT watermark

### Requirement: The checklist

`strata report checklist` MUST emit `reports/prisma-checklist.md` with all 27
items and sub-items, each in one of three states — auto-filled, auto-located, or
author — and a "Location where item is reported" column for the author.
`--status` MUST report how many items remain unaddressed. Item 24c (amendments)
MUST be generated from `criteria-change` events and commit trailers, and item 22
(certainty of evidence) MUST be flagged as author work in v1.

#### Scenario: Search strategy item

- **WHEN** the checklist is generated
- **THEN** item 7 is auto-filled from the verbatim `query` blocks of every search

#### Scenario: Checklist status

- **WHEN** `strata report checklist --status` runs
- **THEN** it reports how many items still need the author
