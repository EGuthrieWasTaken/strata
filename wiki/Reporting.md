# Reporting

The last stage turns the repository into what a manuscript owes its readers: the PRISMA 2020 flow diagram, the
27-item checklist, drafts of the Methods and Results, the reference lists and a supplement for others to
reproduce your review. Everything is **generated from the repository** (numbers from the event log and
`analysis/results/`, never typed in) and marked with the commit it came from. `strata` does **not** write a
Discussion or Conclusion, and does not call a result "significant" or say that anything "causes" anything.

> Run `strata verify`, finish screening, clear every stale decision (`strata rescreen`) and commit before you
> generate anything you intend to use. A DRAFT watermark or a banner about uncommitted changes means exactly
> that.

## The PRISMA 2020 flow diagram

```
strata --why "Flow diagram for the manuscript" prisma
```

writes `reports/prisma.svg` (and commits it). Options: `--format svg|pdf|png|json` (the JSON is shaped as
input for the `PRISMA2020` R package), `--columns one|both` (with `both`, records from other methods:
citation searching, websites, registers, organisations, contacts, get a second column), `--out PATH` (`-` for
standard output).

Every number is **derived** from the log and checked against a set of reconciliation identities (the
records identified, minus duplicates, equal the records screened; those minus the excluded equal the reports
sought; and so on). If one fails, `strata prisma` stops with `E_COUNT_RECONCILE`, naming the identity. While
any decision is stale it refuses (exit code 8), unless you pass `--allow-stale`; and the diagram is
watermarked **DRAFT** whenever screening is unfinished or anything is stale. The exclusion reasons shown at
full text are the criteria your reviewers cited, which is another reason to cite them carefully.

## The checklist

```
strata report checklist --status
```

```
17 auto-filled, 8 auto-located, 17 for the author (of 42 items and sub-items)
Still yours: 1, 2, 3, 4, 13e, 14, 15, 20c, 21, 22, 23a, 23b, 23c, 23d, 24a, 25, 26
```

`strata report checklist` writes the PRISMA 2020 checklist (item wording from Table 1 of Page et al., *BMJ*
2021;372:n71, word for word) with, for each of the 42 items and sub-items, one of three states:

| State | Meaning |
|---|---|
| **auto-filled** | `strata` could answer it from the repository and says what it filled in (e.g. the search dates, the eligibility criteria, the number of studies) |
| **auto-located** | the material exists in the repository; the entry says where (e.g. "the protocol is under `protocol/`") |
| **yours** | only the authors can write it (the abstract, rationale, certainty of evidence, limitations, discussion, ...) |

Some "yours" items can be filled by recording facts in `strata.toml`: the registration
(`[project.registry]`, item 24a), funding and its role (`[project.funding]`, item 25) and competing interests
(`[project.competing_interests]`, item 26): see [Configuration](Configuration).

## Methods, Results and the other sections

```
strata --why "Methods draft" report methods
strata --why "Results draft" report results
strata report manuscript --format docx
```

| `strata report ...` | Produces |
|---|---|
| `methods` | eligibility criteria, sources and search dates, selection process and agreement, data collection, risk of bias, synthesis methods |
| `results` | study selection (with the PRISMA numbers), the synthesis with caveats, sensitivity results |
| `characteristics` | one row per included study (`--format csv`) |
| `amendments` | each change to the criteria after screening began, what it invalidated and what became of it |
| `rob` | the risk-of-bias table (`--format svg` for the traffic-light plot) |
| `checklist` | see above |
| `manuscript` | Methods and Results together with the figures |

Formats: `--format md` (default), `html`, `docx`, `latex` (`html`, `docx` and `latex` need `pandoc`).
`--out PATH` chooses the file (default `reports/<section>.<format>`, committed).

What the generated text does, strictly:

- **Numbers come only from the results files**, so it cannot disagree with them.
- Every part is marked "Generated by strata ... from commit ...: a draft for the author to check against the
  repository".
- It reports what was *recorded*. If you did something `strata` was never told (a hand search), it is not in
  the text.
- It **carries the caveat of every guardrail that fired** (and whether you acknowledged it).
- It describes screening as single-reviewer when the setting is `single`.

A flavour of the generated Results:

> The searches and other sources identified 11 records. After removing 3 before screening (3 duplicates), 8
> records were screened and 2 excluded. Of 6 reports sought for retrieval, 1 could not be retrieved; 5 were
> assessed for eligibility and 1 excluded (Spacing manipulated, n = 1). In total, 4 studies (4 reports) were
> included.

> **The generated Methods have not yet been read by a methodologist.** Read them against the PRISMA 2020
> statement before you rely on them. Which command produces which part of a methods section, and what to check
> before pasting: [Methods-text cookbook](Methods-Text-Cookbook).

## Bibliographies and the supplement

```
strata export bibliography --set included --format ris --out included.ris
strata export bibliography --set excluded-at-fulltext --format csl --out excluded.json
strata export package --out supplement.zip
```

`--set` is `included`, `excluded-at-fulltext` (the appendix of studies excluded at full text), `all-screened`
or `not-retrieved`; formats are `csl` (CSL-JSON, which feeds Pandoc: `pandoc --citeproc
--bibliography=included.json`), `bibtex` and `ris`.

`strata export package` bundles what PRISMA item 27 asks you to make available: the search strategies, the
criteria and their history, the decision log, the extraction data, the analysis specifications and results, the
data licence, and a README naming the commit. It contains **no full texts**. It requires you to declare a
licence for the review data first: `strata config project.license CC-BY-4.0` (then commit it).

## The final checks

1. `strata verify` is clean.
2. `strata status` shows nothing stale and no analysis stale.
3. Everything is committed, and `strata sync` has pushed it.
4. Generate the diagram, checklist, Methods and Results; read them; fill in the checklist items that are yours.
5. Note the commit id in the manuscript: it is the exact state of your review that the numbers came from.
