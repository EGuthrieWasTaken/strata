# 14 — Testing and validation *(normative)*

A meta-analysis tool's failure mode is a wrong number in a published paper. The
testing strategy is proportionate to that.

## 1. Levels

| Level | Scope | Gate |
|---|---|---|
| Unit | Pure functions: normalisation, ids, canonical serialisation, effect-size formulae | Every commit |
| Property | Invariants under generated input (`hypothesis`) | Every commit |
| Golden | Parsers and generated artefacts against committed expected output | Every commit |
| Statistical | Every estimator against `metafor` and published worked examples | Every commit (fixtures) + nightly (live R) |
| Integration | Multi-command flows against a real git repository | Every commit |
| End-to-end | Full review scenarios, including the origin scenario | Every commit |
| Performance | Benchmarks against [13 §1](13-nonfunctional.md) | Every commit, non-blocking; nightly, blocking |
| Fuzz | Parsers against mutated real exports | Nightly |
| Cross-platform | Linux, macOS, Windows | Every commit |
| Manual | Usability sessions with real reviewers | Per milestone |

Coverage floor: 90% line coverage overall; **100% branch coverage** in
`core/fold.py`, `core/ids.py`, `core/canon.py`, `protocol/staleness.py`, and
`stats/escalc.py`. These five modules are where a bug silently corrupts a
published result.

## 2. Property tests *(normative)*

These invariants MUST be tested with generated inputs, not just examples:

| # | Invariant |
|---|---|
| P1 | **Fold determinism.** Folding a shuffled event log yields the same state as folding it in any other order |
| P2 | **Fold idempotence.** Duplicating any subset of events does not change the folded state |
| P3 | **Serialisation round-trip.** `parse(canon(x)) == x` for every schema |
| P4 | **Canonical stability.** `canon(x)` is byte-identical across runs, platforms, and Python hash seeds (`PYTHONHASHSEED` randomised in CI) |
| P5 | **Id determinism.** The same input record yields the same id regardless of import order, file, or platform |
| P6 | **Normalisation idempotence.** `normalise(normalise(s)) == normalise(s)` |
| P7 | **Alias acyclicity.** Any sequence of merges yields a resolvable, acyclic alias graph |
| P8 | **Dedup symmetry.** `score(a, b) == score(b, a)` |
| P9 | **Merge convergence.** Applying two disjoint event sets in either order yields the same state (the property `union` merge relies on) |
| P10 | **Staleness soundness.** For a random criteria change and decision set, every decision *not* marked stale is one whose outcome provably cannot change under the declared direction — tested against a brute-force reference implementation of the rules in [06 §4.2](06-workflow-screening.md) |
| P11 | **Count reconciliation.** For any randomly generated review history, all identities in [09 §2](09-reporting.md) hold |
| P12 | **Effect-size monotonicity.** Increasing `m1` with all else fixed increases `d`; increasing `n` decreases `v` |
| P13 | **Undo inverts.** A decision followed by its undo folds to the pre-decision state |

P10 and P11 are the two that protect the product's central claims and MUST NOT
be weakened to make the suite pass.

## 3. Golden fixtures: parsers

`tests/fixtures/exports/` MUST contain real (or realistically malformed)
exports from, at minimum:

| Platform | Formats |
|---|---|
| PubMed / MEDLINE | `.nbib`, RIS, CSV |
| Ovid (MEDLINE, Embase, PsycINFO) | RIS, `.txt` |
| EBSCOhost (PsycINFO, CINAHL, ERIC) | RIS, CSV |
| Scopus | RIS, CSV, BibTeX |
| Web of Science | RIS, plain text, BibTeX |
| ProQuest | RIS, XML |
| Cochrane CENTRAL | RIS |
| ClinicalTrials.gov | CSV |
| EndNote | XML, RIS |
| Zotero | CSL-JSON, RIS, BibTeX |
| Google Scholar (via Publish or Perish) | CSV |

Each with a committed expected parse. Fixtures MUST include the malformations
that actually occur: BOM, CRLF, missing `ER  -`, CP1252 smart quotes, HTML
entities in titles, multi-line abstracts with inconsistent indentation,
diacritics in author names, corporate authors, missing years, DOIs with trailing
punctuation, and a record with an empty title.

Fixtures MUST be redistributable: either synthesised to mimic the format, or
drawn from records whose metadata is not copyrightable, with sources documented
in `tests/fixtures/SOURCES.md`.

## 4. Statistical validation *(normative)*

This is the section that makes the tool trustworthy.

### 4.1 Against `metafor`

For every estimator in [08](08-analysis.md), a fixture file records `metafor`'s
output for a set of datasets, and the native engine MUST reproduce it to a
relative tolerance of **1e-8** (1e-6 for iteratively fitted `ML`/`REML` `tau^2`).

Fixtures are generated by a committed R script (`tests/statistical/generate.R`)
and committed as JSON, so the test suite runs without R. A **nightly** CI job
regenerates them against current `metafor` and fails on drift, which catches both
our regressions and upstream convention changes.

Required coverage: every `tau^2` estimator, every effect-size measure, Wald and
Knapp–Hartung intervals, `Q`/`I2`/`H2`/`tau^2` CIs, prediction intervals,
meta-regression with continuous and categorical moderators, Egger, Begg,
trim-and-fill, leave-one-out, and the full influence-diagnostics set.

Where `epic` deliberately differs (the prediction-interval df convention,
[08 §4.4](08-analysis.md)), the fixture MUST pin `metafor`'s matching option
explicitly and a comment MUST explain the difference. A silent tolerance bump to
paper over a convention mismatch is the specific failure this rule exists to
prevent.

### 4.2 Against published worked examples

Independent of `metafor`, results MUST match textbook examples whose numbers are
published:

- The BCG vaccine dataset (Colditz et al. 1994), as used throughout the `metafor`
  documentation — log RR, random-effects, meta-regression on absolute latitude.
- Borenstein, Hedges, Higgins & Rothstein, *Introduction to Meta-Analysis* —
  the worked examples in the fixed-effect, random-effects, and heterogeneity
  chapters.
- Hedges & Olkin (1985) worked examples for `g` and its variance.
- A Cochrane review with published RevMan output, for OR and RR with zero cells.

Two independent oracles matter: `metafor` agreement proves we implement the same
convention; textbook agreement proves the convention is the right one.

### 4.3 Numerical edge cases

Explicit tests for: `k = 1`, `k = 2`, all `v_i` identical, one study with
enormous weight, `tau^2` estimated at exactly 0, zero cells in every arm,
perfect correlation (`r = 1`, where Fisher's z is undefined), `n = 3` with
Fisher's z (variance `1/(n-3)` divides by zero), and very large `n` where naive
variance formulae lose precision.

Each MUST either produce the correct value or a specific, actionable error.
Producing `NaN`, `inf`, or a silently wrong number is a test failure.

## 5. End-to-end scenarios

Each is a scripted run against a temporary git repository, asserting on file
contents, counts, and generated output.

| Id | Scenario |
|---|---|
| **E2E-01** | **The origin scenario** ([06 §9](06-workflow-screening.md)): init, criteria v1, two imports, dedup, dual screening, add a criterion, assert the exact stale set, re-screen, assert the flow diagram reconciles and the amendment text is generated. This test is the specification's acceptance criterion and MUST NOT be weakened. |
| E2E-02 | Two collaborators screening concurrently on separate clones, syncing repeatedly, ending with identical repositories and zero manual conflict resolution |
| E2E-03 | Full review to publication: import through analysis, PRISMA diagram, characteristics table, manuscript export, reproducibility package |
| E2E-04 | Criteria loosened (not tightened): assert that exclusions citing it go stale and inclusions do not |
| E2E-05 | A criterion retired after exclusions cited it; assert cascade and re-screen |
| E2E-06 | Cascading staleness: a title/abstract reversal orphans a full-text decision and an extraction, without deleting the extraction |
| E2E-07 | Deduplication after a late fourth import, asserting that earlier manual dedup decisions are not re-raised |
| E2E-08 | Recovery: corrupt a derived file, truncate an event file mid-line, delete the cache, then `epic verify --fix` restores a valid repository |
| E2E-09 | Interrupted screening (SIGKILL mid-session), then resume with no lost decisions |
| E2E-10 | A repository created by an older schema version, migrated forward |
| E2E-11 | Import of a 50,000-record export, asserting performance targets |
| E2E-12 | Determinism: run the full pipeline twice from the same inputs on different platforms; every generated file byte-identical |

## 6. Fuzzing

`ingest.parsers` are fuzzed nightly with `atheris` (or `hypothesis`-driven
mutation) seeded from the real fixture corpus. A parser MUST never hang, exhaust
memory, execute code, or crash with an unhandled exception; it either parses or
reports a `ParseError` with a line number.

## 7. Performance regression

`pytest-benchmark` runs the [13 §1](13-nonfunctional.md) operations against
generated repositories at 1k, 10k, and 50k records. Results are committed per
release. A regression above the hard limit fails CI; a regression above 20% of
the target opens a warning on the pull request.

## 8. Usability testing

At each milestone, at least three sessions with researchers who have not used the
tool, screen-recorded with consent, focused on:

- **M1**: can a non-git user install and complete a screening session?
- **M2**: does a user understand what the staleness report is telling them, and
  do they trust it?
- **M3**: does a methodologist agree the generated Methods text is accurate and
  publishable?

Recorded findings drive a prioritised issue list. This is a release gate, not a
nice-to-have: the entire premise is that the tool is usable by people the current
alternatives fail.
