# 09 — Reporting and PRISMA *(normative)*

The review's output is a manuscript. `strata` generates everything in it that is
mechanically derivable, so the author writes the parts that require judgement and
nothing else.

## 1. PRISMA 2020

`strata` targets the **PRISMA 2020 statement** (Page et al., *BMJ* 2021;372:n71),
which comprises a 27-item checklist and a flow diagram. Extensions
(PRISMA-S for search reporting, PRISMA-ScR for scoping reviews, PRISMA-IPD) are
out of scope for v1 and noted in [16](16-open-questions.md).

> **Implementation note.** The flow-diagram box labels and checklist item
> wording below are reproduced from the published PRISMA 2020 materials to the
> best of this specification's knowledge, but the implementer MUST verify them
> against the official template at prisma-statement.org before shipping, and
> MUST treat the official wording as authoritative where it differs. The PRISMA
> materials are CC BY 4.0, so reproduction is permitted with attribution, which
> generated output MUST carry.

## 2. Counts and reconciliation *(normative)*

`derived/counts.json` holds every number the flow diagram needs, derived from the
event log. The generator MUST assert each identity below and fail with
`E_COUNT_RECONCILE` naming the violated identity if any does not hold. A flow
diagram whose arithmetic does not close is the most visible possible failure of
this tool.

```
identified_total            = sum over searches of records identified (raw rows)
                            + records identified via other methods

removed_before_screening    = duplicates_removed
                            + marked_ineligible_by_automation
                            + removed_other

records_screened            = identified_total - removed_before_screening
records_screened            = records_excluded_tiab + reports_sought

reports_sought              = reports_retrieved + reports_not_retrieved
reports_retrieved           = reports_assessed

reports_assessed            = reports_excluded_ft + reports_included
reports_excluded_ft         = sum over exclusion reasons of count_per_reason

studies_included            <= reports_included          # multiple reports per study
reports_of_included_studies  = reports_included
```

`marked_ineligible_by_automation` is 0 in v1 (no automation classifier ships) but
MUST exist in the schema, because the PRISMA 2020 diagram has a box for it and
adding a field later is a schema bump.

The two-column form of the diagram (database/register searching vs other
methods) requires each count to be partitioned by `via`. Records imported with
`--via citation-searching | website | organisation | registry | contact` populate
the right-hand column.

## 3. The flow diagram

```
$ strata prisma --format svg --columns both
```

Structure (PRISMA 2020, new-reviews variant):

```
IDENTIFICATION
  Records identified from:              Records identified from:
    Databases (n = )                      Websites (n = )
    Registers (n = )                      Organisations (n = )
                                          Citation searching (n = )
  Records removed before screening:
    Duplicate records removed (n = )
    Records marked as ineligible
      by automation tools (n = )
    Records removed for other
      reasons (n = )

SCREENING
  Records screened (n = )  ------------>  Records excluded (n = )
  Reports sought for retrieval (n = ) -->  Reports not retrieved (n = )
  Reports assessed for eligibility (n = ) -> Reports excluded, with reasons:
                                              Reason 1 (n = )
                                              Reason 2 (n = )
INCLUDED
  Studies included in review (n = )
  Reports of included studies (n = )
```

Requirements:

- Exclusion reasons in the "Reports excluded" box are the **criterion labels**
  from `protocol/criteria.yaml`, with counts from the full-text exclusion events.
  Reasons with a count of 0 are omitted. If more than 6 reasons have non-zero
  counts, the smallest are collapsed into "Other reasons (n = )" and the full
  table is emitted alongside, because a diagram with 14 reason lines is
  unreadable.
- Output formats: `svg` (default), `pdf`, `png`, and `json`. The JSON form MUST
  also be emitted in the input shape accepted by the `PRISMA2020` R package, so
  users who prefer that renderer are not locked out.
- `--allow-stale` is required to render while any decision is stale
  ([01 §4](01-domain-model.md)), and the rendered diagram MUST then carry a
  visible "DRAFT — screening incomplete" watermark.
- The diagram MUST be regenerated by `strata verify` and compared byte-for-byte.

## 4. The checklist

```
$ strata report checklist
```

Emits `reports/prisma-checklist.md`: all 27 items with sub-items, each with one
of three states:

- **Auto-filled** — `strata` knows the answer and supplies it (item 7 search
  strategies, item 16a selection counts, the flow diagram, item 27 data
  availability, the eligibility criteria of item 5).
- **Auto-located** — `strata` cannot write the prose but knows where the material
  is (item 8 selection process: "2 reviewers, independent, dual, adjudicated by
  ethan; see `strata report methods`").
- **Author** — requires the author's words (item 2 abstract, item 4 rationale,
  items 23a–d discussion).

The checklist file is a working document with a "Location where item is reported"
column the author fills in with page numbers. `strata report checklist --status`
reports how many items remain unaddressed.

Indicative mapping of items `strata` can substantially fill:

| Item | Topic | Source in the repository |
|---|---|---|
| 5 | Eligibility criteria | `protocol/criteria.yaml`, including the full amendment history |
| 6 | Information sources | `protocol/searches/*.yaml` (databases, platforms, dates) |
| 7 | Search strategy | The verbatim `query` blocks |
| 8 | Selection process | `strata.toml` screening config + adjudication events |
| 9 | Data collection process | `extraction/schema.yaml` + reconciliation events |
| 10a/10b | Data items | `protocol/outcomes.yaml`, `protocol/moderators.yaml` |
| 11 | Risk of bias assessment | `rob/instrument.yaml` + assessment events |
| 12 | Effect measures | `analysis/*.yaml` `effect_size` |
| 13a–13f | Synthesis methods | `analysis/*.yaml` model, dependency, heterogeneity, sensitivity |
| 14 | Reporting bias assessment | `analysis/*.yaml` `publication_bias` |
| 16a/16b | Study selection | `derived/counts.json`, flow diagram, exclusion-reason table |
| 17 | Study characteristics | Generated characteristics table (§5) |
| 18 | Risk of bias in studies | Generated traffic-light plot |
| 19/20 | Results of individual studies and syntheses | Forest plots, `estimates.json` |
| 21 | Reporting biases | Funnel plot, Egger, trim-and-fill |
| 22 | Certainty of evidence | GRADE — **not** generated in v1; flagged as author work |
| 24a | Registration and protocol | `strata.toml` `[project.registry]` |
| 24c | Amendments | Generated from `criteria-change` events and commit trailers |
| 27 | Availability of data and code | The repository URL and commit hash |

Item 24c — amendments to the protocol — is the item this whole tool exists to
make truthful, and it is the item most often reported as "none" in published
reviews simply because nobody kept track.

## 5. Generated manuscript sections

```
$ strata report methods      > methods.md
$ strata report results      > results.md
$ strata report characteristics
$ strata report amendments
$ strata report manuscript --format docx|latex|md|html
```

**Methods** prose is assembled from the protocol and configuration: databases and
dates searched, the eligibility criteria in full, the screening process and
reviewer count, the extraction process and agreement, the RoB instrument, and the
synthesis model with its estimator, CI method, and dependency handling. All of
this is currently transcribed by hand and is a routine source of mismatch between
what a review says it did and what it did.

**Results** prose covers the flow counts, study characteristics, the pooled
estimate with CI and prediction interval, heterogeneity, moderator analyses,
publication-bias assessment, and sensitivity analyses.

**Characteristics table** (PRISMA item 17): one row per included study with the
extracted fields chosen by the user, exportable to `docx` and `latex`.

**Amendments** is generated from `criteria-change` events joined to their commit
rationales, as shown in [06 §9](06-workflow-screening.md).

### 5.1 Rules for generated prose *(normative)*

Generated text is a **draft for the author to edit**, and the tool must not
pretend otherwise or overstate what the numbers support.

- Output MUST be marked as generated, with the commit hash it came from.
- Numbers MUST be rendered to the precision the data supports — two decimal
  places for standardised effect sizes, whole percentages for `I2` — and MUST
  never be re-typed from a different computation than the one in
  `estimates.json`.
- Causal language MUST NOT be generated. "Spaced practice improved retention" is
  a claim about the world that the author makes; "the pooled standardised mean
  difference was 0.38 (95% CI 0.28 to 0.48)" is a statement about the data that
  the tool makes.
- Statistical-significance language MUST be avoided in favour of estimates and
  intervals, in line with current reporting guidance.
- Where a guardrail from [08 §8](08-analysis.md) fired, the generated text MUST
  include the corresponding caveat rather than leaving it to the author to
  remember.
- `strata` MUST NOT generate a Discussion or Conclusion. There is no defensible
  mechanical version of those sections, and shipping one would invite exactly
  the sort of unexamined text that makes the literature worse.

## 6. Bibliography

```
$ strata export bibliography --format bibtex|csl|ris --set included
```

Sets: `included`, `excluded-at-fulltext` (needed for the appendix many journals
require), `all-screened`, `not-retrieved`. CSL-JSON output feeds pandoc directly,
so `strata report manuscript --format latex` can produce a document with working
citations from the same source of truth as the analysis.

## 7. The reproducibility package

```
$ strata export package --out spaced-retrieval-supplement.zip
```

Produces everything PRISMA item 27 asks to be made available: the search
strategies, the criteria with their full version history, the screening decision
log, the extraction data, the analysis specifications, the results, and a
`README` explaining the layout and the commit hash it came from. This is intended
to be attached to a journal submission or deposited in a repository such as OSF
or Zenodo.

Because full texts are never committed, the package contains no third-party
copyrighted material and can be shared without clearance.
